## [1.2.1] - 2026-08-21

- hackathon status no longer suggests `hackathon run demo-coach --duration 60` for the `verifying` stage — the `--duration` flag does not exist on `hackathon run`. The suggestion now points to `hackathon run fast-verify` then `hackathon run demo-coach`.

## [1.1.0] - 2026-08-20

### Added

- **`hackathon run <skill> --chain`** — follows Format v2 `dependencies` and
  prints (or, with `--apply`, pre-fills) every upstream skill in
  topological order before the target skill. Refuses with a clear error when
  the dependency graph contains a cycle. Example: `hackathon run
demo-rehearsal --chain` emits `scope-knife -> fast-verify -> demo-coach ->
demo-rehearsal`.
- **Per-skill version pin** — `hackathon skills pin` now records each skill's
  own Format v2 `version` (falling back to the pack version) instead of only
  the pack-level version. `skills diff` reports a `^ vX -> vY` line when a
  skill's own version changes and the pin-file schema bumps to `1.1`.
- **Pluggable embedding matcher backend** — `match_skill` (MCP) now honors
  `HACKATHON_EMBED_BACKEND`, an HTTP endpoint that accepts the utterance +
  skill descriptions and returns a ranking. Any transport or schema failure
  falls back to the local token/synonym matcher (`HACKATHON_EMBED_TIMEOUT_SECONDS`
  defaults to 3). The offline matcher remains the default.
- **`skill_chain` MCP tool** (14th tool) — returns the dependency-ordered
  skill chain for a target skill over JSON-RPC.
- **`src/harness/embed.ts`** — the embed-backend adapter with a documented
  request/response contract and a tolerant response-shape parser.
- **12 new unit tests** (5 for `--chain`, 3 for per-skill pin, 3 for the
  embed backend, 1 tools/list bump). Total: 152/152 passing (was 140/140).

### Changed

- `skills pin` now writes `.hackathon/` (parent dir) if it does not exist,
  so pinning works before `hackathon init`.
- `skills list` prints a `version` column (the skill's own Format v2 version).
- The MCP server now tracks in-flight requests and exits cleanly after all
  pending handlers resolve, which is required for the async embed backend.

### Compatibility

- No breaking changes. `--chain` is opt-in; per-skill pin entries gain a
  truthful `version` field; the embed backend only activates when
  `HACKATHON_EMBED_BACKEND` is set.

## [1.0.0] - 2026-08-20

### Added

- **`hackathon skills graph`** — emits a Mermaid / DOT / ASCII graph of skill
  `dependencies` and `side_effects` from Format v2 frontmatter. Supports
  `--format <mermaid|dot|ascii|md>` and `--type <all|deps|effects>`.
  Detects and warns on dependency cycles (refused in the loop).
- **Auto-derived state diagram** in `docs/skills/index.md`. The hand-maintained
  ASCII state-machine diagram is replaced by two Mermaid blocks generated by
  `scripts/regen-skill-graphs.mjs` (which calls `hackathon skills graph` and
  writes the result). Regenerating after a frontmatter change is one script
  invocation.
- **Cycle detection** in the dependency graph (`scope_knife --> team_roster
--> scope_knife` and similar) caught 4 real metadata bugs during v1.0.0
  work; fixed by tightening which skills count as upstream dependencies vs
  pairings.
- **8 new unit tests** in `tests/unit/v100-skills-graph.test.mjs` covering
  mermaid / dot / ascii / md outputs, --type filtering, and cycle-detection
  exit codes. Total: 140/140 passing (was 132/132).
- **Updated `tests/unit/mcp.test.mjs`** to expect 13 tools (was 12).
- **`scripts/regen-skill-graphs.mjs`** — convenience wrapper that regenerates
  `docs/skills/{dependencies,state-writes}.md` in one shot.

### Changed

- **Skill metadata cleanup** — removed dependency cycles from idea-clarify,
  team-roster, time-box, scope-knife, and decision-log. The convention is now
  "depends on" = "consumes the other skill output". Pairing relationships
  live in `tags` and the SKILL.md prose, not in `dependencies`.
- **`docs/skills/index.md`** rewritten — the old ASCII state diagram is
  replaced with the auto-derived Mermaid blocks.

### Compatibility

- No breaking changes. Format v2 fields remain optional.
- `validate-skill` does not enforce dependency metadata yet; only warns.
  Cycle detection is reported as a warning, not an error.

### Migration guide

#### From 0.9.x to 1.0.0

No code changes required. To take advantage of the new graph commands:

hackathon skills graph # Mermaid flowchart to stdout
hackathon skills graph --format dot # Graphviz DOT
hackathon skills graph --format ascii # quick CLI listing
node scripts/regen-skill-graphs.mjs # refresh docs/skills/*.md

#### From pre-0.9.x (Format v1) to 1.0.0

If you authored skills before Skill Format v2, add the following frontmatter
fields to each SKILL.md so it participates in `skills search` and `skills graph`:

```yaml
version: 1.0
category: scoping # or one of building|verifying|demoing|judging|shipping|recovering|lifecycle
tags: ['<label>', '<label>']
dependencies: []
side_effects: []
triggers: ['<phrase>', '<phrase>']
```

The fields are validated by `hackathon validate-skill <dir>`; missing version
prints a WARN. There is no migration deadline for Format v1 skills — they
keep working — but Format v2 unlocks the discovery tools.

## [0.8.0] - 2026-08-20

### Added

- **LLM judge backend** — `judge-sim` now honors `HACKATHON_JUDGE_BACKEND` (an HTTP endpoint). When set, it POSTs the state inputs and uses the returned per-dimension scores; any transport or schema failure falls back to the heuristic scorer with `judge_source: "heuristic-fallback"`. `HACKATHON_JUDGE_TIMEOUT_SECONDS` defaults to 3.
- **Ship webhook** — `ship-pack` now honors `HACKATHON_SHIP_WEBHOOK` and posts the audit as JSON after writing `ship.json`. Delivery is non-fatal: failure only prints a warning.
- **ADR-0008** documenting the v0.7 semantic fallback, v0.8 pluggable backends, and the validation no-op fix.
- **Acceptance coverage for fallback paths** — judge-sim and ship-pack tests now exercise unreachable backends and assert graceful degradation.

### Fixed

- **`judge_questions` schema violation** — `score.py` emitted 0-1 questions for several dimensions, violating `review.schema.json`'s `minItems: 2`. A `pad_questions()` helper now guarantees 2-3 questions for both heuristic and remote scoring.
- **Validation no-op** — the `validate` npm script and shell acceptance/integration checks called `dist/cli/commands/validate.js` directly (a module with no CLI entrypoint), so schema validation always exited 0 without doing anything. They now call `node dist/cli/index.js validate`.

### Changed

- `review.schema.json` gains optional `judge_source` (`heuristic`, `llm`, `heuristic-fallback`) and `judge_backend` fields.
- `judge-sim` and `ship-pack` SKILL.md + docs pages document the new environment variables.

### Compatibility

- No breaking changes. New fields are optional; local heuristic behavior remains the default when no backend/webhook is configured.

## [0.3.0] - 2026-08-19

### Added

- **Two new skills** (the pack now ships 8):
  - `idea-clarify` — pre-`scope-knife` step that turns a one-paragraph brief into a one-page brief with a concrete `demo_goal` and `mvp_axis`. Refuses vague answers.
  - `pivot` — mid-build redirect. Reads the 5 state files, computes a preserve/cut/rewrite table, refuses to run if at least 1 KEEP feature does not survive (otherwise it is a rewrite, not a pivot).

Returns 0 on pass, 1 on any error.
- **CLI: `hackathon diff <a> <b>`** — object-aware JSON diff between two state files or two `.hackathon/state/` directories. Stable-key array matching (matches by `name` or `id` if present, else by index). Supports `--stat` and `--json`.
- **CLI: `hackathon mcp`** — start the Model Context Protocol server on stdio (JSON-RPC 2.0). Exposes 4 tools: `list_skills`, `get_skill`, `match_skill`, `status`. Compatible with Codex, Claude Code, and Cursor.

- **MCP server** (`src/mcp/server.ts`) — minimal JSON-RPC 2.0 stdio server. No third-party SDK; the harness is the value, the MCP wrapper is a thin transport. Verified via 4 new unit tests.
- **`recovery-runbook/scripts/build_recovery.py`** — completes the recovery loop (was the missing piece: `recovery-runbook/SKILL.md` describes the runbook, this script actually writes it). CI skill-protocol lint enforces shebang + `--repo-root` + `VERSION = "1.0"` for every `scripts/*.py`.
- **ADR-0004: Skills are extensible via CLI + JSON Schema pairing** — documents the new-skill + validate-skill + schema-pairing pattern. Updated `docs/architecture/adr/index.md` accordingly.
- **Skill detail pages for `idea-clarify` and `pivot`** in `docs/skills/`, with mkdocs nav entries.
- **23 new unit tests** (frontmatter, trigger, state, status, flow, validate-skill, new-skill, diff, mcp). Total: 69/69 passing.
- **`scripts/scaffold-skills.mjs`** — convenience script that scaffolds both `idea-clarify` and `pivot` in one shot. Used during the v0.3.0 build; safe to re-run.

### Changed

- `CONTRIBUTING.md` expanded with the "Add a new skill" walkthrough (4 steps: scaffold → fill in → add schema → `validate-skill`).
- Skill matcher scoring now exposes a `reasons` array per candidate, so `--debug` output explains _why_ a skill won.
- `docs/skills/index.md` state-machine diagram now shows the 8 skills and the `idea-clarify` + `pivot` pre/post stages.
- README "Six skills" / "v1 ships 6 skills done well" lines updated to reflect 8 skills.

### Fixed

- `validate-skill` regex for the `Do not invoke` clause was using `\\s+` (literal backslash + s) instead of `\s+` (whitespace class). This made the check fail for `when_to_use` values that wrapped "do not invoke" across a line break, producing a spurious warning on `pivot` and any future skill that wraps the clause. Replaced with the correct whitespace-class regex; verified 0 warnings on `pivot`, `idea-clarify`, and `scope-knife`.
